# Universes

A registry of projects that forked the ROBOTIKO v2.0 **method** (MIT-licensed
— see [LICENSE](LICENSE)) to build their own concept-album universe, the way
[CONTRIBUTING.md §1(a)](CONTRIBUTING.md#1-two-ways-to-contribute) describes.

> New here? [FORKING.md](FORKING.md) is the step-by-step, and
> [docs/fork-dry-run.md](docs/fork-dry-run.md) is the author's own timed run of it
> against a second universe — including the one thing that broke.

**This list is empty right now, by design, not by failure.** The repo goes
public around EP10's release — this file is here from day one so the first
fork has somewhere to be counted. Entry #1 could be yours.

## What qualifies

Any project that took the pipeline — the skills, the scripts, the two
human gates, the stage-gated structure — and pointed it at a *different*
story. It doesn't have to be finished. It doesn't have to replace
everything (see the checklist in the
[universe showcase template](.github/ISSUE_TEMPLATE/universe_showcase.md) —
a universe that only swapped `_management/master.md` and kept the rest
still counts, honestly labeled). It doesn't have to sound anything like
CyberAnatolian prog rock. What it does need:

- Its own canon (`_management/master.md` replaced, not edited)
- Its own cast / state machine (`_assets/cast/character_profiles.json`
  replaced)
- Its own house style (the mandatory visual/video suffixes replaced)

It should **not** be a copy of the ROBOTIKO story with names changed — that's
not what "your own universe" means, and it would run against the
[LICENSE-CONTENT](LICENSE-CONTENT) terms on the original creative content.

## How to register

Open an issue using the
[universe showcase template](.github/ISSUE_TEMPLATE/universe_showcase.md).
Include what you changed, a link to where it lives, and — the most useful
part — one thing that broke when your canon hit assumptions the pipeline
made for ROBOTIKO specifically. That feedback is how the method gets more
general; see the invitations in [ROADMAP.md](ROADMAP.md).

Once registered, an entry gets added below by the maintainer.
